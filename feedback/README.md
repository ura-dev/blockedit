# feedback — 運用実績の記録

`reports/`はgit管理対象外(`.gitignore`)の生ログで、実行のたびに増える。ここは
その中から「後で参照する価値がある」ものだけを人力で選んで残す、git管理下の場所。

## ファイル

`{タスク名}_{日付}.md`(`reports/`と同じ命名規則)。1ファイル1実行、もしくは
同一タスクで複数回試した一連の流れをまとめて1ファイルにしてもよい。

## 書く内容

- 実行したタイミング・タスクの目的
- 期待通りだった点/期待通りに動かなかった点のギャップ
- ギャップの原因(few-shotの偏り、抽象度が高すぎる分類だった、等)
- 改良案が出た場合は、その場で直さずに issue なり別の置き場なりへ起こす
  (このフォルダは実績の記録であって、改善提案の置き場ではない)
