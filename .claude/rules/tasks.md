# タスクを足す前に — 判断ラダー

1. **正規表現で書けるか** — 書けるなら方式1。LLMを呼ばない
2. **1件ごとの分類・置換か** — 方式2。これがこの道具の範囲
3. **意味を保った散文の書き換えか** — 局所性ゲートが原理的に効かない。持ち込まない
4. **設計判断か** — 人が決める

`(para, unit)` を `task.SUPPORTED` に足したくなったら3段目に来ている。**実測のない
組み合わせを足さない。**足すなら `bench/` で測って、勝率と件数をコメントに残す。

数えられる値・判定できる値をモデルに聞かない。行数・件数・パス・ハッシュはランナーが出す。

## 必須の宣言には理由がある

- `UNIT="line"` の方式2に `FEWSHOT` — 素の指示は9行中8行を**系統的に**間違えた。
  誤答実例1つで4/4に回復する。ブロックスワップ側は本文自体が逐語コピーの手本になるので不要
- `SCOPE="match"` に `RESIDUE` — 完了判定に `PATTERN` を流用すると完全形しか拾わず、
  半端な破壊を「残っていない」と誤判定する(実測で2件取りこぼした)

**`PATTERN` の広さがそのままモデルの裁量になる。**狭く取れるタスクほど安全で、
リンクの畳み込みのように正規表現で書けるものは1段目で終わらせる。

`tasks/` の3本は見本。ゲームや個人プロジェクト由来の語をここに書かない。
