# blockedit — ブロック単位の機械編集ランナー

## 何が困っていたか

多数ファイルにまたがる機械的な編集 — リンク記法の畳み込み、行の分類、参照文の削除 —
をClaudeにやらせると、変更が1行でもファイル全体が文脈を通る。読んで、書いて、次へ。
**コストは変更の大きさではなく、ドキュメントの大きさで決まる。**

119ファイルのdocsに対するリンク畳み込みで、該当したのは3ファイル・17,437バイト。
そのうち実際に触るブロックは328バイト(1.9%)しかない。

blockeditは残りを文脈に載せない。Claudeが書くのはタスクファイル1本、読むのは
`files= hit= applied= rejected=` の1行。ドキュメントの本文は一度も通らない。

## 仕組み

対象の抽出・ローカルLLMとの往復・機械検証・適用・レポート出力はランナーが持つ。
呼ぶのは OpenAI互換のサーバ(KoboldCpp / FreeToken で確認)で、実測はすべて
Gemma4 26B を載せたもの。**LLMの生出力もランナーを出ない。**

安全性は「モデルが正しいこと」に依存しない。ランナーがブロックの外側と行の終端文字を
所有し、モデルの出力はブロックの位置にしか入らない。よって「変更範囲外はバイト同一」が
構造的に保証される。

骨格は4段。**行スコープの編集も段落スワップも、この骨格の上のタスク型2つでしかない。**

1. **選ぶ** — 正規表現で対象を決める。探索をモデルにさせない
2. **送る** — 当たった塊だけ。周りは送らない
3. **所有する** — ランナーが周りを持つ
4. **棄却する** — 機械検証に落ちたら適用しない

## 実行

**このランナーは編集対象のリポジトリの外に置く。**対象は起動時に渡す。

```
uv run python blockedit.py tasks/foo.py --root ../your-repo
```

`--root` を省いた場合は環境変数 `BLOCKEDIT_ROOT`、それも無ければ**カレント
ディレクトリ**のgitルートを対象にする(ランナーの置き場所ではない)。推測の結果が
ランナー自身のリポジトリになったときは、黙って自分を編集せずに起動を拒否する。

```
uv run python blockedit.py tasks/foo.py --select-only  # 選択だけ見る(0トークン)
uv run python blockedit.py tasks/foo.py               # dry-run(既定)
uv run python blockedit.py tasks/foo.py --limit 5     # 先頭5ブロックだけで試走
uv run python blockedit.py tasks/foo.py --apply       # 書き込む
uv run python blockedit_selftest.py                   # ゲートと分割の回帰(0トークン)
```

標準出力は1〜2行に固定される(`files= hit= applied= rejected=` と `git diff --stat`)。
**dry-runの中身はレポートファイルに出る** — 落ちたブロックと、受理したブロックの前後の
両方。初回はまず `--select-only` を見て、次にdry-runのレポートを読む。

CLIの上書きは**狭める方向にだけ**用意してある(`--files` / `--limit` / `--select-only`)。
`UNIT` と `SCOPE` は安全境界なので実行時オプションにしない。振って測るのは `bench/` の
仕事で、本番のランナーは振れない。

## タスクファイルの書き方

`tasks/*.py` に置く。必須は `FILES` `PATTERN` `UNIT` `SCOPE` と、
**`transform` か `INSTRUCTION` のどちらか**。

### 2本の軸

```python
UNIT  = "line" | "para" | "heading" | "full"   # モデルに見せる塊
SCOPE = "unit" | "match"                        # 塊のうち改変を許す範囲
```

行スコープの編集は「行を見せて行全体を書き換える」ので `unit`、ブロックスワップは
「段落を見せて一致した文だけ直す」ので `match`。**範囲の広さがそのままモデルに与える
裁量**になる。

通る組み合わせは実測のある4つだけで、外れたものは起動時に落ちる。

| UNIT | SCOPE | 何ができるか |
|---|---|---|
| `line` | `unit` | 行を1行に変換する(分類・言い換え) |
| `para` | `match` | 段落を見せ、一致範囲だけ直す |
| `heading` | `match` | 同上。塊が大きいぶん遅い |
| `full` | `match` | 割らない。8本中7本までしか通らないので常用しない |

`(para, unit)` — 段落を丸ごと書き直させる — は開けていない。意味を保った散文の書き換えは
判断ラダーの3段目で、局所性ゲートが原理的に効かないため。

### 方式1: 正規表現で書ける(LLMを呼ばない — まずこれを検討する)

```python
FILES = ["docs/**/*.md"]              # 対象リポジトリのルートからのglob
UNIT, SCOPE = "line", "unit"
PATTERN = re.compile(r"...")          # 対象を選ぶ。抽出はモデルにさせない
def transform(body): ...              # 塊 -> 塊
def preserve(body): ...               # 任意。消えてはならない部分文字列のリスト
def validate(before, after): ...      # 任意。落ちる理由の文字列 or None
```

### 方式2: 1件ごとに判断が要る(Gemma4を呼ぶ)

`transform` を定義せず、代わりに:

```python
INSTRUCTION = "..."                   # 塊を書き直させる指示
FEWSHOT = [(入力, 正解出力), ...]      # UNIT="line" では必須。無いと起動を拒否する
PITFALL = (入力, 誤答, 正解)           # 任意だが強く推奨
RESIDUE = re.compile(...)             # SCOPE="match" では必須。完了判定の痕跡
EXCLUDE = ["docs/_archive/**/*.md"]   # 任意
LEVEL = 2                             # 任意。UNIT="heading" の見出しレベル
MAX_BLOCK_BYTES = 8000                # 任意。超えるブロックは送らずに落とす
SAMPLER = {...}                       # 任意。既定は反復抑制のみ(DRY無効)
RETRY_TEMPERATURE = 0.6               # 任意。既定は振り直さない
```

`FEWSHOT` が行スコープで必須なのは実測の結果。素の指示だと9行中8行を**系統的に**
間違え、誤答実例を1つ足すだけで4/4に回復した。このサイズのモデルは抽象的な言い換えより
誤答の実例に反応する。ブロックスワップ側は要らない — ブロック自身が逐語コピーの手本になる。

**`SCOPE="match"` で `RESIDUE` を省略したタスクは起動を拒否する。**完了判定に `PATTERN` を
流用すると完全形しか拾わないので、「開き括弧だけ消えた」半端な破壊を見逃す(実測で2件
取りこぼした)。`SCOPE="unit"` は塊ごと差し替わるので `PATTERN` の流用でよく、痕跡が
残ってよいタスク(出力が原文と無関係になる分類など)は `ALLOW_PATTERN_REMAIN` で外す。

**`PATTERN` の広さがモデルの裁量になる。**局所性ゲートは一致範囲を*その部分文字列*で
置き換えることしか許さない。文を丸ごと消すなら文全体を範囲に取る必要があり、逆に
リンク記法の畳み込み(`[表示](パス)` → `表示`)は文を範囲にすると通らない。狭く取れる
タスクほど安全で、畳み込みのように正規表現で書ける操作はそもそもここに持ち込まない。

呼び出しは温度0、出力上限は入力長から自動で決まる(暴走の物理的な上限)。**指示と本文の
区切りは空行で固定**されていて選べない — `---` で連結していた頃、モデルがそれを水平線として
本文に写した(空行に替えるだけで段落分割は 2/8 → 8/8)。

## 常に効いている検証ゲート

タスク側の `validate` の前に、ランナーが全件で以下をかける。落ちたブロックは
**適用せずレポートに送り、次へ進む**。ゲートは2列あり、片方だけでは穴が開く。

**仕事をしていない側**

- 無変更(no-op)ではないか
- `RESIDUE` の痕跡が出力に残っていないか

**やりすぎている側**

- `SCOPE="match"`: 対象外の行を触っていないか / 一致範囲の外側が1文字も動いていないか
- `SCOPE="unit"`: 行数が増えていないか / 出力が異常に長くないか(元の3倍+40文字)
- `preserve()` が返した部分文字列が全部残っているか
- ブロック内で改行コードが混在していないか(推測して貼り戻さない)

ゲートの手前で、**塊の先頭・末尾の空白はランナーが原文どおりに戻す**(終端文字と同じ
理由で、字下げと行末の空白はモデルの領分ではない)。行スコープは塊全体が改変可なので
局所性ゲートが効かず、字下げの落ちた行がそのまま通っていた。箇条書きの `- ` のような
**記号**は空白ではないので戻らない。落としてほしくない記号は `preserve()` に書く。

範囲だけを見ていた頃、E4Bが8本中4本を素通りさせた。逆に完了だけでは、対象行の上で
太字を剥がす類のやりすぎが通る。2列は対になっている。

## 制約

- 方式2は OpenAI互換の `/v1/chat/completions` を喋るサーバが起動済みであること。既定は
  `http://127.0.0.1:5001/v1`(KoboldCpp)で、`--base-url` で変更する。**動作を確認したのは
  KoboldCpp と FreeToken(`http://127.0.0.1:1919/v1`)の2つ。**ローカルのGPUを他の常駐
  プロセスと共有している場合、そちらを止めてから回す。
- **README の勝率はすべて KoboldCpp + Gemma4 26B での実測。**サーバやモデルを替えたら
  数字は移らないので `bench/` で測り直す。FreeToken は連続スペースを n-1 個にして返す
  既知のバグがあり(現物で再現)、**行の内側の連続スペース**は守れない — 字下げと行末は
  ランナーが復元するが、`` `a  b` `` のような内側は `preserve()` で拾う。
- 数えられる値・判定できる値をモデルに聞かない。行数・件数・パス・ハッシュはランナーが出す。
- 作業ブランチ上で `--apply` する。dry-runと `--limit` での試走を先に通す。
- ゲートに落ちた出力を温度0で投げ直さない(貪欲デコードは同じバイトを返す)。
  棄却してレポートに送り、判断は呼び出し元に返す。

## 運用実績

`reports/` はgit管理対象外の生ログ。後で参照する価値がある実行結果は `feedback/` に
人力で拾って残す(書き方は `feedback/README.md` 参照)。新しいタスクファイルを書く前に、
同種のタスク形状の記録がないか一読する。

`tasks/` に入っている3本はいずれも見本で、そのまま使うものではない。
`example_link_flatten.py` が方式1(正規表現・LLMを呼ばない)、
`example_heading_labels.py` が方式2の `SCOPE="unit"`(1行ずつLLMに判断させる)、
`example_reference_links.py` が方式2の `SCOPE="match"`(段落を見せ、一致した文だけ
消す)。`blockedit_selftest.py` が既定で読むのも3本目。

計測ハーネスは `bench/`。分割・ゲート・サンプラーは本体をそのまま import していて、
複製していない — 1バイトでも違うと計測が本番を代表しなくなるため。
